# Публичная страница и заявки DachaHub

## Адреса

- `/` — публичная страница продукта, возможности и предложение бесплатного пилота.
- `/Product/Pricing` — условия пилота и дальнейшего обслуживания.
- `/Product/Privacy` — уведомление об использовании персональных данных.
- `/Product/Demo` — выбор страницы и роли в рабочем тестовом товариществе; вход без регистрации и пароля.
- `/Product/Management` — отдельная галерея для бухгалтера (финансовый обзор, расходы) и администратора (участники, участки). Под каждым предпросмотром доступен вход прямо в показанный раздел с нужной ролью.
- `/Product/Try/...` — страницы тестового товарищества с отдельной учебной базой посетителя. Данные можно изменять.
- `/Product/Request` — форма запроса демонстрации и обсуждения подключения.
- `/Platform/Requests` — входящие заявки для действующего администратора платформы. Доступ администратора отдельного товарищества не подходит.
- `/Platform/Requests/Details/{id}` — карточка заявки с этапом, заметками и датами пилота.
- `/neftyanik/` и адреса других товариществ — прежние страницы входа. Общий адрес `/` больше не перенаправляет в «Нефтяник».

Публичные страницы доступны на украинском, русском и английском. Выбранный язык передаётся между публичными страницами в параметре `culture`.

## Тестовое товарищество

С первого экрана доступны две явные кнопки: «Войти в кабинет» под подписью «Уже зарегистрированы?» и «Попробовать без регистрации» для тестового товарищества. Вход в кабинет ведёт на существующую страницу входа «Нефтяника». Галерея открывает личный кабинет, показания электроэнергии, финансовый обзор или список участников с соответствующей ролью.

Для каждого браузера создаётся отдельная SQLite-база в памяти процесса, заполненная только вымышленными участниками, участками, начислениями, платежами и показаниями. Обычная база SQL Server не используется для операций демо. Сессия живёт 30 минут с момента создания; переходы между ролями этот срок не продлевают. По окончании вход в старую сессию закрывается, а база освобождается после завершения текущих запросов (очистка запускается раз в минуту). Следующий вход создаёт исходные данные заново. Есть кнопка немедленного перезапуска. Перезапуск приложения также удаляет все учебные сессии.

Демо использует отдельную cookie `DachaHub.Demo`; она не авторизует посетителя в настоящем товариществе или панели платформы. Разделы платформы и обычные страницы управления входом недоступны внутри демо. Для выхода из настоящего аккаунта сохраняется обычный механизм Identity.

Ограничение: 15 входов/переключений роли с одного IP за 15 минут, до 40 одновременно хранимых учебных сессий. Вместимость настраивается через `PublicDemo:MaxSessions` (1–100). При нескольких процессах сервера требуется закрепление посетителя за одним процессом; общий кластерный склад сессий не реализован. SQLite используется только для демо; представление дробных чисел адаптировано для её агрегатных запросов, точные финансовые данные основной системы остаются в SQL Server.

Галерея содержит 18 настоящих JPEG-скриншотов: шесть разделов на русском, украинском и английском языках в `wwwroot/images/demo/`. Снимки получены из учебного товарищества, персональные данные рабочего товарищества не используются. Изображения можно увеличить; отдельная кнопка открывает показанный раздел в изменяемом демо с нужной ролью. После изменения интерфейса снимки следует обновить. Главная и галерея проверены в браузере на широком экране и на ширине телефона 390 px.

## Приём и обработка заявок

Форма сохраняет имя, название товарищества, выбранный способ связи (email, звонок, Viber или Telegram), email и/или телефон, необязательные число участков и сообщение, время подачи в UTC и версию согласия `pilot-contact-v2`. Данные находятся в отдельной таблице `DemoRequests` и не создают аккаунт, товарищество или подписку. Они доступны только администраторам платформы через защищённую страницу. Персональные данные не передаются в URL подтверждения.

Оператор открывает «Заявки», связывается с клиентом самостоятельно и нажимает «Отметить: связались». Раздел «Связались» хранит обработанные заявки; их можно вернуть в новые. При настроенной служебной почте администратор получает уведомление со ссылкой на защищённую панель. Ответ клиенту автоматически не отправляется.

Форма использует серверную проверку полей, защиту от поддельных запросов, скрытое поле для отсечения простых ботов и лимиты: 5 отправок с одного IP за 15 минут и 100 отправок в целом за 15 минут. Просмотр формы не расходует лимит. За доверенным прокси необходимо использовать существующую конфигурацию ForwardedHeaders, иначе посетители могут разделять один IP-лимит.

## Подготовка базы

Перед запуском новой версии примените все миграции до `20261017083126_AddSalesPilotCards` включительно обычным процессом развёртывания. Миграции заявок создают таблицу `DemoRequests`, поля уведомлений, способы связи и карточки пилота; финансовые таблицы они не меняют. `AddSalesRequestContactMethods` и `AddSalesPilotCards` сохраняют прежние контакты и версии согласия.

```powershell
dotnet ef database update --project src/Neftyanik.Portal.Infrastructure --startup-project src/Neftyanik.Portal.Web --context ApplicationDbContext
```

Команду выполняют с настройками нужного окружения. При разработке приложение уже применяет миграции при запуске. В остальных окружениях автоматические миграции отключены.

Слово `product` зарезервировано для публичных страниц. Миграция SQL Server остановится, если товарищество уже использует такой адрес: сначала нужно согласовать и изменить его адрес. Не публикуйте новую версию до успешного применения миграции.

При подготовке изменения рабочая база не обновлялась.

## Первые подключения

Публичное предложение: бесплатный пилот на 3 месяца для первых трёх товариществ. Включает работу портала, базовую настройку и помощь с согласованным объёмом переноса данных. Отсчёт начинается с согласованной даты запуска, а не с отправки заявки. Участие, объём помощи и дата подтверждаются лично. Автоматического учёта мест, срока пилота или отключения доступа в приложении нет: программу подключения ведёт владелец.

После пилота стоимость продолжения согласуется отдельно, до его завершения. Платная подписка автоматически не возникает, списания не выполняются. Дополнительные функции, интеграции и дополнительный перенос истории в бесплатный пилот не входят и требуют отдельного согласования объёма и стоимости.

Пилот использует обычное товарищество с рабочими данными и стандартными ролями, а не 30-минутное демо. Данные пилота не сбрасываются механизмом демо. До запуска согласуются резервное копирование, восстановление и формат передачи данных при завершении участия.

Начать предлагается с бухгалтера, администратора и небольшой группы участников и собирать обратную связь. Публикация отзыва или примера использования требует отдельного согласия. На сайте не указываются вымышленные отзывы, клиенты или оставшееся количество мест.

Перед рабочим запуском нужно обеспечить технические условия сохранения и передачи данных, определить ответственного за заявки и правила хранения контактов, согласовать условия пилота и оформить документы с реквизитами оператора сервиса. Публичные страницы не включают приём банковских платежей.
Для ответа по email почта обязательна; для звонка, Viber или Telegram обязателен телефон с кодом страны. Телефон сохраняется в нормализованном формате. Старые заявки сохраняют способ связи email. Контакты отображаются только в защищённой панели платформы; уведомление по почте по-прежнему не содержит контактов клиента. Миграция AddSalesRequestContactMethods добавляет только поля в таблицу заявок.

## Карточки пилота

Администратор платформы открывает карточку из списка заявок (`/Platform/Requests/Details/{id}`). Доступ наследует защиту раздела платформы; администраторы товариществ не получают доступ к заявкам.

Карточка хранит этап (новая заявка, связались, показ назначен, показ проведён, пилот идёт, пилот завершён, отказ, вернуться позже), внутренние заметки до 4000 символов, следующее действие до 500 символов и его дату, согласованные даты начала и окончания пилота. Для активного и завершённого пилота обязательны обе даты, окончание не может предшествовать началу. Даты календарные, без времени и часового пояса. Они не создают расписание уведомлений, подписку или автоматическое отключение доступа. Трёхмесячный срок согласуется оператором вручную.

Сохранение любого этапа кроме новой заявки отмечает обращение как обработанное. Вернуть продвинутый этап в новые можно через карточку, выбрав «Новая заявка»; быстрый переход в списке открывает карточку. Этап, следующее действие и сроки видны в списке заявок. Конфликт одновременного редактирования требует обновления страницы, изменения другого администратора не перезаписываются.

Миграция AddSalesPilotCards добавляет только поля таблицы DemoRequests. Прежние обращения получают этап «Новая заявка» или «Связались» по ContactedAtUtc. Рабочие данные товариществ этой миграцией не меняются.
## Выгрузка данных товарищества

Страница `/Administration/Export` доступна администраторам и бухгалтерам текущего товарищества. Ссылки находятся в финансовом обзоре и панели администрирования. Участники и администраторы других товариществ не получают доступ к его выгрузке. Выгрузка использует текущий контекст и обычные фильтры товарищества; параметра выбора чужого товарищества нет. Демо выгружает свою учебную базу.

По кнопке «Скачать Excel» формируется XLSX с шестью листами на текущем языке: описание, участники, участки, владение, остатки участников, остатки участков. Включаются неактивные записи и завершённые связи владения. В финансовых остатках учитываются все сохранённые неотменённые начисления и платежи, в том числе с будущей датой; отбора периода нет. Остаток равен начислениям минус платежи, положительное значение — долг, отрицательное — переплата. Долг участника не переносится на текущего владельца участка. Для участков применяется тот же расчёт распределений платежей, что и в финансовом обзоре. Последние строки финансовых листов показывают суммы без участника или участка. Два представления остатков нельзя складывать между собой.

Данные читаются в транзакции Serializable до формирования файла, с сохранением механизма повторных попыток провайдера базы. Скачивание выполняется POST-запросом с защитой от подделки запроса; ответ не кэшируется. Строковые данные записываются как текст, а суммы — числами. Файл формируется в памяти и не сохраняется в общедоступные каталоги сервера. Миграция базы для этой функции не нужна.

Выгрузка предназначена для сверки и передачи основных данных, не является резервной копией: полной истории операций, документов, счетчиков и показаний в ней нет. Пароли и сведения для входа не включаются. Передача полного набора данных при завершении обслуживания согласуется отдельно.
