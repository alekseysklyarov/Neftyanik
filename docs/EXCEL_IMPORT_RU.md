# Импорт из Excel в DachaHub

Администратор товарищества открывает **Администрирование → Импорт из Excel** (`/{slug}/Administration/Import`).

1. Скачать шаблон `.xlsx` со страницы. Заполнять лист `Import` со второй строки, сохраняя заголовки. На листе `Readme` есть инструкция.
2. Указать код участника внутри файла, ФИО, контакты, номер участка, адрес, площадь в м², кадастровый номер и начальный остаток в гривнах. Необязательные поля можно оставить пустыми.
3. Для нескольких участков владельца повторить его код, ФИО и контакты. Каждый участок указывается один раз. Можно отдельно добавить участника без участка (без остатка) или участок без владельца.
4. Остаток относится к участку и его владельцу: положительное число — долг, отрицательное — переплата, пустая ячейка — ноль. Нельзя повторять общий остаток владельца на каждом его участке.
5. Выбрать дату переноса, загрузить файл и проверить строки, количество участников/участков, суммы долгов и переплат.
6. Исправить все ошибки в исходном файле и повторить проверку. Нажать «Подтвердить импорт». Все строки сохраняются вместе; при ошибке операция откатывается.

Ограничения первой версии: до 1000 строк и 5 МБ; только `.xlsx`, без пароля и формул; фиксированный шаблон с русскими, украинскими или английскими заголовками. Числа допускают точку или запятую и не более двух десятичных знаков. Для номеров участков с ведущими нулями и телефонов используйте текстовые ячейки (в шаблоне уже настроены). Дата переноса — с 2000 года по текущую дату.

Импорт создаёт новые карточки. Он не обновляет существующих участников/участки, не создаёт учётных записей для входа и не меняет текущих владельцев. Совпадения ФИО с существующими участниками блокируют импорт и требуют ручной проверки; однофамильцев с полностью совпадающими ФИО добавляют через обычные карточки. Выгрузка из раздела экспорта не является шаблоном импорта.

Начальный долг сохраняется отдельным начислением «Начальный остаток», переплата — операцией «Перенос переплаты». Плательщик и участок фиксируются при загрузке. Переплата участвует в остатке лицевого счёта и дальнейшем зачёте авансов, но не увеличивает кассу, банк или доходы фондов. Для неё нет платёжки и исправления как обычного поступления денег; доступна штатная отмена. Фактические остатки кассы и банка вводятся отдельно в финансовых настройках.

Предпросмотр защищён от изменения, привязан к администратору и товариществу и действует 30 минут. Данные проверяются повторно при подтверждении. Маркер загрузки и финансовый журнал записываются в той же транзакции; повторное подтверждение не создаёт дублей. Ошибки распаковки, лишние столбцы, формулы, повторяющиеся участки, конфликтующие сведения владельца и некорректные контакты блокируют сохранение. Данные других товариществ не участвуют в проверке совпадений.

Изменения структуры базы данных не требуются. Для денежных остатков используется дополнительное значение перечисления `PaymentMethod.OpeningBalance`; обычные формы оплаты его не предлагают. Для начала работы нужно пересобрать и перезапустить приложение.
