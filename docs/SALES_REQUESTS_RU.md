# Заявки на подключение и уведомления Gmail

## Как обрабатываются заявки

1. Посетитель отправляет форму `/Product/Request`. Заявка сначала сохраняется в базе.
2. Фоновый обработчик раз в минуту выбирает до пяти новых необработанных заявок и отправляет уведомления владельцу почты `sklyarova.natasha.v@gmail.com`.
3. Ответственный за эту почту открывает `/Platform/Requests`, нажимает «Ответить по email», отправляет ответ в своей почтовой программе и отмечает «Связались».
4. Для уже обработанных заявок неотправленные уведомления не нужны. Их можно вернуть в новые через кабинет.

Клиенту не отправляется автоматическое письмо от имени владельца. Кнопка ответа только открывает почтовую программу. Письмо администратору содержит номер заявки и ссылку на кабинет; контакты и сообщение клиента остаются в защищённом кабинете.

## Включение отправки в Visual Studio

Адрес получателя, отправителя, сервер `smtp.gmail.com` и порт `587` уже настроены в Web/appsettings.json. Пароль там не хранится.

1. Для Gmail с включённой двухэтапной проверкой создайте отдельный пароль приложения DachaHub: https://myaccount.google.com/apppasswords . Если эта возможность недоступна для аккаунта, потребуется другой способ отправки почты.
2. В Visual Studio нажмите правой кнопкой на проект **Neftyanik.Portal.Web** → **Управление секретами пользователя / Manage User Secrets**.
3. Добавьте свойство `PlatformSmtp:Password` со значением пароля приложения в существующий JSON, сохранив остальные настройки. Не отправляйте пароль в чат и не добавляйте его в файлы проекта.
4. Перезапустите сайт. В разделе «Заявки» исчезнет сообщение «Почта ещё не подключена». Это означает наличие настроек, а не подтверждение доставки. У конкретной заявки после успешной отправки появится время передачи письма почтовому серверу.

Документация Google:
- Пароли приложений: https://support.google.com/accounts/answer/185833?hl=en
- Параметры SMTP: https://support.google.com/mail/answer/7104828?hl=en

## База данных и публикация

Добавлена миграция `20261017064609_AddSalesRequestNotifications`: три поля состояния уведомления и индекс. Рабочая база при подготовке кода не изменялась. В Development миграции применяются при запуске; в других окружениях миграцию нужно применить штатной процедурой обновления до запуска новой версии.

На сервере пароль задаётся через защищённые настройки окружения (`PlatformSmtp__Password`), а не через локальные User Secrets. `SalesNotifications:InboxUrl` следует заполнить абсолютной HTTPS-ссылкой на `/Platform/Requests` опубликованного сайта. Пока она пуста, в письме указан путь к кабинету. Получатель и включение отправки задаются через `SalesNotifications:Recipient` и `SalesNotifications:Enabled`.

## Сбои и повторные попытки

Сбой SMTP не отменяет сохранённую заявку. Повторная попытка выполняется не раньше чем через десять минут. Если приложение было остановлено в процессе отправки, резервирование заявки истекает через пять минут. Очередь переживает перезапуск, а атомарное резервирование разделяет работу нескольких экземпляров приложения.

SMTP не обеспечивает отправку «ровно один раз»: при обрыве после принятия письма сервером, но до сохранения результата, возможно повторное уведомление с тем же номером заявки. Время в кабинете означает принятие письма SMTP-сервером и не гарантирует попадание во входящие.

В окружении Testing фоновая отправка отключена. При подготовке изменений выполнена сборка; тесты и отправка настоящих писем не запускались.
