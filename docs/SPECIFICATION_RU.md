# Проектирование базы данных

## Портал садового товарищества «Нефтяник»

## 1. Общие принципы

Приложение использует:

* Microsoft SQL Server;
* Entity Framework Core;
* ASP.NET Core Identity;
* миграции EF Core для создания и обновления базы данных.

SQL-таблицы не должны создаваться вручную на первом этапе. Структура базы определяется Entity-классами и конфигурациями Entity Framework Core.

Все денежные значения хранятся как:

```csharp
decimal(18, 2)
```

Все даты и время действий системы хранятся в UTC:

```csharp
DateTimeOffset
```

Показания электросчетчиков хранятся как:

```csharp
decimal(18, 3)
```

Удаление важных финансовых данных физически не выполняется. Для отмены операций используются статусы, сторнирование или признак `IsCancelled`.

# 2. Пользователи и роли

Для регистрации, авторизации и управления ролями используется ASP.NET Core Identity.

## ApplicationUser

Расширяет стандартный класс:

```csharp
IdentityUser
```

Дополнительные поля:

| Поле        | Тип             | Описание                |
| ----------- | --------------- | ----------------------- |
| Id          | string          | Идентификатор Identity  |

| LastName    | string          | Фамилия                 |

| LastLoginAt | DateTimeOffset? | Последний вход          |

Пароли не хранятся в собственных таблицах приложения. Их хранением занимается ASP.NET Core Identity.

## Роли

Система использует следующие роли:

* `Administrator`;
* `Accountant`;
* `Member`.

### Administrator

Может управлять:

* пользователями;
* ролями;
* участками;
* счетчиками;
* тарифами;
* ежегодными взносами;
* новостями;
* документами;
* настройками системы.

### Accountant

Может:

* просматривать участников и участки;
* обрабатывать показания;
* создавать начисления;
* регистрировать платежи;
* распределять платежи;
* регистрировать расходы;
* просматривать финансовые отчеты.

### Member

Может:

* просматривать свои участки;
* передавать показания;
* просматривать начисления;
* просматривать задолженность;
* просматривать платежи;
* читать новости и документы.

# 6. Связь счетчиков и участков

Один счетчик может обслуживать один или несколько участков одного владельца.

## MeterPlot

| Поле      | Тип             | Описание        |
| --------- | --------------- | --------------- |
| MeterId   | int             | Счетчик         |
| PlotId    | int             | Участок         |
| ValidFrom | DateTimeOffset  | Начало связи    |
| ValidTo   | DateTimeOffset? | Окончание связи |

Составной ключ:

```text
MeterId + PlotId + ValidFrom
```

Связь:

```text
ElectricityMeter * ────── * Plot
```

Ограничения бизнес-логики:

* участок не должен одновременно относиться к двум активным индивидуальным счетчикам;
* индивидуальный счетчик может быть связан с несколькими участками;
* связанные участки должны принадлежать одному владельцу;
* общий счетчик товарищества не связывается с отдельными участками через `MeterPlot`.

### Начисление электроэнергии

Для однотарифного счетчика:

```text
Потребление = текущее показание − предыдущее показание

Начисление = потребление × тариф
```

Для двухтарифного счетчика:

```text
Дневное начисление =
дневное потребление × дневной тариф

Ночное начисление =
ночное потребление × ночной тариф

Итого =
дневное начисление + ночное начисление
```

Если один счетчик обслуживает несколько участков, начисление создается на владельца счетчика. Оно не умножается на количество участков.

### Начисление членского взноса

Начисление создается отдельно для каждого участка:

```text
Amount = MembershipFeeRate.AmountPerPlot
```

# 12. Распределение платежей

Один платеж может закрывать несколько начислений.

## PaymentAllocation

| Поле      | Тип            | Описание             |
| --------- | -------------- | -------------------- |
| Id        | long           | Первичный ключ       |
| PaymentId | long           | Платеж               |
| ChargeId  | long           | Начисление           |
| Amount    | decimal        | Распределенная сумма |
| CreatedAt | DateTimeOffset | Дата распределения   |

Правила:

* сумма распределений не может превышать сумму платежа;
* сумма распределений по начислению не может превышать остаток начисления;
* нераспределенная часть платежа считается авансом;
* бухгалтер может изменить распределение;
* при автоматическом распределении сначала закрываются самые старые начисления;
* порядок типов начислений должен задаваться настройкой системы.

Рекомендуемый порядок по умолчанию:

1. задолженность по электроэнергии;
2. членские взносы;
3. другие начисления.

# 13. Расчет задолженности

Остаток конкретного начисления:

```text
ChargeBalance =
Charge.Amount
− сумма PaymentAllocation.Amount
```

Общая задолженность пользователя:

```text
TotalDebt =
сумма остатков всех активных начислений
```

Аванс пользователя:

```text
Advance =
сумма активных платежей
− сумма распределений платежей
```

Итоговый баланс:

```text
AccountBalance =
TotalDebt − Advance
```

Интерпретация:

* значение больше нуля — задолженность;
* значение меньше нуля — переплата;
* ноль — задолженности нет.

Задолженность не должна храниться отдельным изменяемым полем пользователя. Она рассчитывается из начислений и распределений платежей.

# 15. Общий счетчик товарищества

Общий счетчик хранится в таблице `ElectricityMeter`:

```text
MeterKind = Common
TariffMode = DayNight
```

Его показания хранятся в `MeterReading`.

На первом этапе показания общего счетчика используются для отчетности и сравнения.

## Расчет потерь

```text
Общее потребление =
потребление общего счетчика

Учтенное потребление =
сумма потребления индивидуальных счетчиков

Потери =
общее потребление − учтенное потребление
```

Процент потерь:

```text
LossPercentage =
LossConsumption / CommonConsumption × 100
```

Потери не распределяются между пользователями автоматически на первом этапе.

# 22. Начальные данные

При первом запуске необходимо создать роли:

```text
Administrator
Accountant
Member
```

Начальные настройки:

```text
Название: Садовое товарищество «Нефтяник»

Тариф: 5,00 грн/кВт·ч

Ежегодный взнос: 500,00 грн за участок
```

Начальные категории расходов:

```text
Оплата электроэнергии
Ремонт электросети
Ремонт дорог
Охрана
Вывоз мусора
Обслуживание территории
Административные расходы
Налоги и банковские комиссии
Прочее
```

Учетная запись администратора не должна иметь пароль, жестко записанный в исходном коде. Данные первого администратора должны передаваться через переменные окружения или User Secrets.

# 23. Первая версия приложения

В первую рабочую версию должны войти:

1. ASP.NET Core Identity.
2. Роли Administrator, Accountant и Member.
3. Управление пользователями.
4. Управление участками.
5. Управление индивидуальными счетчиками.
6. Ввод и подтверждение показаний.
7. Тариф 5 грн/кВт·ч с историей.
8. Автоматическое начисление электроэнергии.
9. Ежегодный взнос 500 грн за участок.
10. Регистрация платежей.
11. Распределение платежей по начислениям.
12. Расчет задолженности.
13. Учет расходов.
14. Новости.
15. Документы.
16. Общий двухтарифный счетчик.
17. Базовые финансовые отчеты.
18. Журнал критических действий.

Онлайн-оплата, Telegram-уведомления, электронные голосования и автоматическое распределение потерь относятся к будущим версиям.
